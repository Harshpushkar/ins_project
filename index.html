The basics

The vocabulary behind every cipher on this page.

Plaintext

The original, readable message before encryption, e.g. HELLO.

Ciphertext

The scrambled, unreadable result of encryption, e.g. KHOOR.

Encryption

Converting plaintext into ciphertext using a secret key.

Decryption

The reverse step: turning ciphertext back into readable plaintext.

How it works

A quick look under the hood of each algorithm.

Caesar Cipher

Every letter is shifted by a fixed number of positions given by the key. With a shift of 3, A becomes D, B becomes E, and so on. Letters wrap around at the end of the alphabet (Z + 3 becomes C). Spaces, numbers and punctuation are left unchanged. Decryption shifts back the same amount. 

Plaintext :  HELLO WORLD
Key       :  3
Ciphertext:  KHOOR ZRUOG

Decrypt   :  KHOOR ZRUOG  --(shift -3)-->  HELLO WORLD
Vigenère Cipher

A Caesar cipher with a moving shift. Each letter of a keyword sets how far to shift the matching plaintext letter: A = 0, B = 1, … Z = 25. The keyword repeats for the whole message, and only moves forward on letters, so spaces and punctuation are preserved. 

Plaintext :  ATTACK AT DAWN
Keyword   :  LEMON LEMONLEM
Ciphertext:  LXFOPV EF RNHR

Decrypt   :  LXFOPV EF RNHR  --(keyword LEMON)-->  ATTACK AT DAWN
XOR Cipher

Each character is turned into its byte value and combined with the bytes of the key using a bitwise XOR (the key repeats as needed). XOR is its own inverse, so applying the same key twice restores the text. Output is shown in hexadecimal because XOR produces binary data, not readable text. 

Plaintext :  Hi
Key       :  k
Bytes     :  H(0x48) xor k(0x6B) = 0x23
             i(0x69) xor k(0x6B) = 0x02
Ciphertext(hex): 23 02

Decrypt   :  23 02  --(key k)-->  Hi

Educational use only. These classical ciphers are a great way to learn the ideas behind cryptography, but they are not secure and must never be used to protect real-world communication. Modern security needs algorithms such as AES and RSA with careful key management.
